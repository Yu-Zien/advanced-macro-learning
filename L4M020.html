把手算步骤写成可靠的迭代循环

来源：Lecture4.pdf，PDF 第 47–48 页。

本步讲解

手算矩阵可以直接变成循环。关键是这一轮所有状态都用同一份旧值，算完后才替换；否则就不再是本讲表格使用的同步迭代。

v_old = [0.0] * len(grid)
for iteration in range(max_iterations):
    v_new, policy = [], []
    for k in grid:
        choices = []
        for j, next_k in enumerate(grid):
            consumption = k**alpha - next_k
            if consumption > 0:
                q = log(consumption) + beta * v_old[j]
                choices.append((q, next_k))
        if not choices:
            raise ValueError("这个状态没有可行控制")
        best_value, best_k = max(choices, key=lambda pair: pair[0])
        v_new.append(best_value)
        policy.append(best_k)
    difference = max(abs(x-y) for x, y in zip(v_new, v_old))
    v_old = v_new
    if difference < tolerance:
        break
else:
    raise RuntimeError("未在规定迭代数内收敛")

这段是算法示范，需事先给定网格、参数与对数函数。并列最优时这里保留枚举中先出现的控制。先检查消费再取对数；不可行选择也可给负无穷值，但仍需处理整行都不可行的情况。完成后再做一次更新计算残差；不把达到最大迭代次数也写成“收敛”。

例题 A · 编辑示范

某实现把续接项写成 beta * v_old[i]，其中 i 是当前状态行号。问题是什么？

A 解答

查看示范解答

续接价值取决于候选下一期状态，应该查候选列号 j。用行号会让所有候选拥有同一未来价值，无法正确权衡储蓄。

练习 B · 补充练习

新增练习 · 训练本课已演示的方法

某实现在检查消费前先计算 log(consumption)，遇到负消费后才尝试忽略该选项；还有一行没有任何可行控制。分别如何修复？

B 解答

尝试后查看参考解

必须先判断消费严格大于零，再取对数或将不可行目标置为负无穷；整行没有可行控制应明确报错或修正网格，而非返回一个伪政策。

一句小结

正确索引、同步更新、先筛可行性和明确停止原因，是数值算法的基本要求。
